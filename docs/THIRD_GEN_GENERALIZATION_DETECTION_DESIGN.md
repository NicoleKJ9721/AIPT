# 第三代工业缺陷泛化检测设计

**状态：设计与基础能力阶段。** 本文档描述目标架构和验收原则；除固定工位 ROI 外，异常检测模型和工位配方数据模型尚未接入 AIPT 运行时。

## 1. 定义与边界

第三代平台要解决的是：在极少样本、仅有正常品，甚至没有本工位样本时，发现未知缺陷或异常区域。

它与现有能力的边界如下：

| 能力 | 适用输入 | 目标 | 是否可直接自动判定 |
| :--- | :--- | :--- | :--- |
| YOLO 检测/分割 | 已标注的已知缺陷 | 输出缺陷类别、框或掩膜 | 可以，前提是现场验证通过 |
| 少样本正常品异常检测 | 1–100 张合格品 | 学习“正常外观”，输出异常热图和分数 | 仅在阈值校准和现场验证后 |
| 零样本异常候选发现 | 没有本工位训练数据 | 找出可疑区域，辅助建立数据集 | 首版不可以，必须复核 |
| SAM3 / FastSAM 分割 | 点、框或文字等交互提示 | 生成前景/工件/忽略区掩膜 | 不是缺陷分类或异常判定 |

零样本没有“无数据即可安全放行”的承诺。其价值是缩短建库和发现未知问题，而不是替代质量责任。

## 2. 产品入口与用户流程

新增一级入口 **泛化检测**，并在项目下新增可复用的 **工位配方**。

```text
项目
  → 工位配方（固定 ROI、忽略区、定位/对齐、图像质量门控）
  → 选择检测模式
      ├─ 已知缺陷：YOLO
      ├─ 少样本正常品：PatchCore / EfficientAD
      ├─ 零样本探索：WinCLIP / AnomalyCLIP
      └─ 混合：YOLO + 异常检测
  → 阈值校准与验证集评估
  → 复核中心（通过 / 异常 / 待复核）
  → 部署配方（模型、工位配方、阈值、版本）
```

工位配方必须独立于原图：原图不可变；裁剪、掩膜、对齐和预处理均保存为派生、可版本化配置。

## 3. 模型分层

### 3.1 少样本正常品：生产优先

- **PatchCore**：优先的准确率基线，采用正常样本特征记忆库，适合中等吞吐量工位。
- **EfficientAD**：面向更低时延的候选方案，需以现场误报率和延迟共同验收。

建议通过独立服务接入，而不是直接混入 YOLO 运行环境。两类模型的依赖、训练产物、阈值和评估指标都与检测模型不同。

### 3.2 零样本：探索优先

- **WinCLIP / AnomalyCLIP**：输出图像级分数与像素热图，用于候选发现、数据筛选和复核队列。
- **新型视觉基础模型异常方法**：仅作为受控对比基准。接入前须审计来源代码、固定版本与权重，并使用工位数据验证。

### 3.3 已知缺陷与融合

已知类别继续使用 YOLO。部署时应保留三个明确的结果：

- `known_defect`：YOLO 命中已知缺陷；
- `anomaly`：异常模型超过已校准阈值；
- `review`：模型冲突、低置信度或图像质量不合格。

不能把异常热图强行映射成某个未被训练过的缺陷类别。

## 4. UI 设计

### 4.1 工位配方页

- 原图预览上拖拽固定 ROI；当前版本已先提供百分比 ROI 配置。
- 可增加忽略区、多边形前景掩膜、定位基准和光照/清晰度质量门控。
- 显示“原图不变、配方版本可回滚”的提示。

### 4.2 泛化检测向导

1. 选择工位配方和模式。
2. 零样本模式要求确认“仅候选发现”；少样本模式展示正常品数量和覆盖情况。
3. 显示模型建议、资源需求、异常热图和阈值滑杆。
4. 使用独立验证集校准阈值，展示漏检、误报、延迟和不确定样本。
5. 发布为部署配方，而不是只发布单个权重文件。

### 4.3 复核中心

- 原图、ROI、热图、YOLO 结果并排显示。
- 操作者只能选择通过、异常或待复核，并填写必要原因。
- 复核结果进入主动学习池，供后续人工标注和 YOLO 再训练。

## 5. 背景与关键区域策略

稳定工位不要先做永久背景删除，应按以下顺序处理：

1. 固定 ROI；
2. 忽略区（夹具、反光、时间戳等）；
3. 工件定位/对齐（模板、特征点或标记物）；
4. 需要时由分割模型辅助生成前景掩膜；
5. 将掩膜作为配方输入，不覆盖原始图片。

这能保持训练、回溯、阈值校准和现场调试的一致性。

## 6. 验收标准

- 以按日期、相机、光照、产品批次切分的真实数据评估，不能只做随机切分。
- 记录图像级异常召回、误报率、像素级定位质量、单位图像延迟和显存占用。
- 单独进行“留出缺陷类型”实验，评估未知缺陷发现能力。
- 零样本模式的首个验收目标是高价值候选召回和复核效率，不是自动拦截率。
- 每次部署必须冻结模型权重、ROI/掩膜、预处理、阈值、评估集版本和操作者版本。
