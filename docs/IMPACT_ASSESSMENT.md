# 影响评估报告（Impact Assessment）

日期：2026-01-04

## 1. 变更范围概览

本次变更以“质量加固”为主，未改变平台既定业务流程（项目 → 数据集 → 标注 → 增强/训练）。

涉及模块：
- 前端：类型/构建修复、Hooks 稳定性修复、目录上传类型补齐
- 后端：ZIP 导入流式化、日志可观测性增强、SQLite/存储辅助能力补测
- 工程化：新增一键校验脚本（lint/security/test/build）

## 2. 兼容性与接口影响

### 2.1 后端 API
- **无破坏性变更**：现有路由与请求/响应格式保持不变。
- 导入逻辑内部优化为流式写入，不影响接口行为，仅降低内存峰值与提升稳定性。

### 2.2 前端模块
- 仅对内部实现与类型进行收敛修复；构建产物与路由流程保持一致。
- `buttonVariants` / `badgeVariants` 等仅用于 UI 组件内部的导出已移除；当前仓库内无引用（`npm run build` 已验证）。

## 3. 风险评估与回滚策略

### 3.1 风险点
- 日志增强可能在极端情况下增加少量 I/O（主要为异常路径），正常路径影响可忽略。
- ZIP 流式导入对分块写入更敏感：若磁盘空间不足/权限不足，将更早失败并返回明确错误。

### 3.2 回滚策略
- 代码级回滚：恢复 `backend/main.py` 中 ZIP 导入旧实现与 `backend/storage.py` 的旧写入方式即可（不涉及数据库 schema 变更）。
- 配置级回滚：无新增必需配置项；验证脚本不影响运行时。

## 4. 性能与稳定性收益

- 数据集 ZIP 导入：避免把文件内容一次性加载到内存，显著降低大包导入时的内存峰值。
- 前端 Toast：避免重复订阅导致的潜在泄漏与重复渲染问题。
- 后端异常记录：问题可追踪性提升，减少“失败但无日志”的定位成本。

## 5. 验收方式

推荐在仓库根目录执行：

```bash
scripts/verify.bat
```

该脚本会依次运行：
- 后端：ruff、bandit、pytest + coverage
- 前端：lint、build
